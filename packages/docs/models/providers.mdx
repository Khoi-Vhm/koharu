The translation picker combines local and hosted backends. A selection records the provider, model ID, optional local quantization, and vision-input setting.

## Available connections

| Connection          | Providers                                                          |
| ------------------- | ------------------------------------------------------------------ |
| Local inference     | GGUF models through llama.cpp                                      |
| Hosted models       | Codex, OpenAI, Gemini, Claude, Grok, MiniMax, DeepSeek, OpenRouter |
| Compatible servers  | LM Studio and OpenAI-compatible endpoints                          |
| Machine translation | DeepL, Google Cloud Translation, Caiyun                            |

Each provider owns its endpoint defaults, request mapping, and model discovery. Available models can change independently of these docs.

<Steps>
  <Step title='Save the connection'>
    Open **Settings → Providers**, choose a provider, and fill in its fields. Hosted services
    require credentials. A local compatible server needs its base URL; LM Studio defaults to
    `http://localhost:1234` and OpenAI-compatible defaults to `http://localhost:11434/v1`. Whether a
    local server needs a secret depends on that server.
  </Step>
  <Step title='Select a model'>
    Open the processing selector or **Settings → Translation**. Opening the processing selector, or
    the Settings page, refreshes provider discovery. An unreachable provider may have no discovered
    models even while its saved settings remain intact.
  </Step>
  <Step title='Choose whether to include the page image'>
    **Vision** is on by default and the switch stays available for every model. If the selected
    model does not accept images, Koharu drops the image from the request. OpenAI-compatible
    endpoints are assumed to accept images, so turn the switch off when the server cannot handle
    image messages.
  </Step>
  <Step title='Try one page'>
    Check the source OCR, run translation on the current page, and review the response before
    processing a chapter.
  </Step>
</Steps>

## Codex account

[Sign in with Codex in the Agent panel](/agent/setup), then choose a Codex model in the translation picker.
Codex uses that ChatGPT authorization instead of an API key. The Agent and translator have
independent model selections and share the same account; signing out affects both.

## OpenCode Zen / Console

Use **OpenAI-compatible** in **Settings → Providers** with your OpenCode API key:

- **Base URL:** `https://opencode.ai/inference/openai/v1`
- **Model list URL (optional):** `https://opencode.ai/inference/v1/models`

OpenCode serves its model catalog separately from its chat endpoint. For other compatible
servers, leave the model list URL empty to use `<base URL>/models`. Reopen the translation
picker after saving to refresh discovery. Turn off **Vision** for text-only models.
Free-tier chat models require the OpenCode client; use a supported paid model in Koharu.
See [OpenCode's model documentation](https://opencode.ai/v2/docs/console/models/).

## Credentials and privacy

Provider secrets use the operating system's secure credential service. Non-secret endpoint settings live in `~/.koharu/config.toml`.

Local models keep prompts and text on your machine after download. Hosted providers receive request content and apply their own retention terms. Local detection and OCR do not make a hosted translation request local.

<Warning>
  Keep keys out of project instructions, text layers, and configuration files. Save credentials
  through **Settings → Providers**.
</Warning>
